# SEC returned 401 or 403

Symptom: a job exits with code 4 and a critical alert "SEC blocked the request".

SEC blocks traffic that has no real User-Agent or that exceeds 10 requests per second.
The run stops at the first 403 on purpose: continuing would extend the block.

1. Check `reitstreet config`: `sec_user_agent` must be a real name and email, and
   `sec_requests_per_second` must be 10 or less (default 8).
2. Check nothing else on the same network address is calling SEC (another script, a second
   copy of this pipeline on another machine).
3. Wait at least 10 minutes. SEC blocks are usually lifted after the traffic stops.
4. Resume: `reitstreet sec-sync --resume <run_id>` (run_id from `reitstreet status`).
5. If 403s persist for hours, lower `requests_per_second` to 4 and try again.

Nothing is lost: items that finished before the block are checkpointed, and the failed
request is in `raw_fetch` with its status.
